# Review decisions and deliberate exclusions

This is a specification review, not a completed code/Git audit.

1. Removed synthetic production status, arbitrary takeover probabilities and illustrative dynamics sliders from the product requirements. Synthetic fixtures remain only for isolated testing.
2. Separated current source collection, current authorized operational telemetry, and historical/controlled replay. A new article about an old campaign is not a new live detection.
3. Replaced a forced global severity ladder with separate scope, evidence, authorization, attribution, persistence, control and coverage axes. No automatic internet-scale declaration.
4. Bound response verification to effective control time, action initiation, target and identity lineage, with external corroboration. A successful API response to a revocation request is not effective containment.
5. Required source/claim provenance and explicit disagreement handling. Self-reported model/provider identity and shared cloud infrastructure remain weak evidence.
6. Required independent release approval and baseline limits rather than promises that the assistant or another agent is trustworthy. Unknown changes are preserved and reviewed rather than labeled sabotage.
7. Put Vercel behind a real application/data architecture, with durable worker hosting, authentication and reachability explicitly addressed. No hidden localhost assumption or endless serverless loop.
8. Prevented retrieved content and news from activating rules or executing actions. Collection/parsing has no containment or release authority.
9. Added no-data behavior, source completeness checks, unresolved-case persistence, held-out evaluation and actual networking tests.
10. No paid resources, cloud writes, repository changes, connector approval retries or deployment actions were executed to create this package.

Remaining execution dependencies: recover actual source/repository context; owner-approved collector scope; real identity/service access; a durable worker host if continuous service is desired; real source and event evidence; independent release authority; and verification of actual Vercel/GitHub plan features. These are not satisfied merely by this prompt.
